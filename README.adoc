== What is CCCP?

The *Campaign for Cooler Coding and Programming* is the philosophical and ethical foundation of the link:https://github.com/hyperpolymath/rhodium-standard-repositories[Rhodium Standard Repositories (RSR)] framework.

CCCP defines *principles and policies* for building software that is:

* *Emotionally safe* — development without shame or anxiety
* *Technically excellent* — type-safe, memory-safe, formally verified
* *Politically autonomous* — independent of Big Tech lock-in

== The Four Temperatures of "Cooler"

[cols="1,3"]
|===
| Temperature | Meaning

| *Emotional*
| Reduced anxiety through reversibility, safe experimentation, no shame in mistakes

| *Computational*
| Efficient systems, no unnecessary cycles, minimal runtime overhead

| *Social*
| Warm community with graduated trust, cool-headed technical decisions

| *Political*
| Resistance to monopolistic tooling, anti-corporate lock-in, autonomy through offline-first and keepable-software design
|===

== Core Principles

=== 1. Post-JavaScript Liberation

Rejecting the npm/node ecosystem's fragility in favor of:

* *AffineScript* — affine types, compiles to typed-wasm or ESM
* *Rust* — Systems programming with memory safety
* *Bun* — the default runtime when JavaScript is unavoidable (then Deno, pnpm, npm)

=== 2. Offline-First as Autonomy

* Work continues without constant connectivity
* No cloud-dependent tooling
* SaltRover for offline repository management
* Local execution where practical
* Offline-capable operation where possible
* Exportable user data
* No mandatory remote execution for the core experience unless clearly justified
* Hosted services may enhance the project, but must not become hostage architecture

This principle extends into the <<_keepable_software,Keepable Software>> section below: offline-first is one of the ways CCCP keeps the user's software, data, and work from disappearing behind someone else's switch.

=== 3. Distributed State Without Coordination

* *CRDTs* eliminate locking and cache invalidation
* Conflict-free by design
* No single point of failure

=== 4. Formal Verification as Mutual Aid

* Correctness is an act of solidarity
* SPARK/Ada for safety-critical paths
* Type systems prevent bugs before they happen

=== 5. Community Over Ego

* TPCF (Tri-Perimeter Contribution Framework)
* Graduated trust without gatekeeping
* Collective ownership patterns

=== 6. Language Polyglotism as Resistance

Using diverse languages resists monoculture:

[cols="1,2"]
|===
| Approved | Banned

| AffineScript, Rust, Zig, Idris2, Gleam, Elixir, OCaml, Haskell, Ada, Julia, Nickel, Guile Scheme, Vue
| TypeScript, ReScript, Python, Ruby, Go, V-lang, Java/Kotlin, Swift, React, Angular, Flutter/Dart, Makefiles, Node.js, yarn
|===

TypeScript is allowed only where AffineScript cannot reach (protocol glue,
runtime APIs), and only as a transitional step (standards §1.2).

=== Allowed Languages

[cols="1,2,2"]
|===
| Language | Use Case | Notes

| *AffineScript*
| Primary application code
| Affine-typed; compiles to typed-wasm or ESM

| *Rust*
| Systems, performance, WASM, CLI tools
| Creusot + Pearlite and Verus for proofs

| *Zig*
| FFI layers and C interop
| With an Idris2 ABI

| *Idris2*, *Agda*, *Lean*, *Rocq*
| APIs, engineering properties, theory
| Per standards `PROOF-POLICY.adoc`

| *Gleam*, *Elixir*
| Backend services
| BEAM or JS target

| *OCaml*, *Haskell*
| Compilers and language tooling
| Strong type systems

| *Ada* / *SPARK*
| Safety-critical systems
| SPARK verification

| *Julia*
| Data processing, batch scripts, numerics
| Replaces Python for data work

| *Nickel*
| Configuration language
| Type-safe configs

| *Guile Scheme* / *A2ML*
| State and meta files
| `.machine_readable/6a2/*.a2ml`

| *Vue*
| Web UI, where a framework is needed
| Instead of React or Angular

| *Bash/POSIX Shell*, *just*
| Scripts, automation, task running
| Keep minimal; `just` replaces Make
|===

=== JavaScript Runtimes

JavaScript runs only where AffineScript cannot (protocol glue, runtime
APIs). Reach for the first tool that can do the job:

. *Bun*: the default. `package.json` plus `bun.lock`.
. *Deno*: second. It reads the same `package.json`.
. *pnpm*: third, where an upstream toolchain needs a `node_modules` layout.
. *npm*: last resort only. It never keeps a tracked lock.

Node.js is never the runtime a project targets, and yarn is not used. If npm
is the last resort, the Node.js it needs is a build-time tool only.

=== Banned Languages

[cols="1,2,2"]
|===
| Banned | Replacement | Rationale

| *TypeScript*
| AffineScript
| Unsound gradual typing

| *ReScript*
| AffineScript
| Superseded by AffineScript

| *Python*
| Julia / Rust / AffineScript
| No static types. No exceptions.

| *Ruby*
| Rust / Julia / shell
| No static types

| *Go*
| Rust
| Error handling, generics

| *V-lang*
| Rust / Zig
| Unstable language and toolchain

| *Java/Kotlin*
| Rust / Tauri / Dioxus
| JVM overhead, platform lock-in

| *Swift*
| Tauri / Dioxus
| Platform lock-in

| *React*, *React Native*, *Angular*
| Vue (web), Tauri / Dioxus (mobile)
| Big Tech governance

| *Flutter/Dart*
| Tauri / Dioxus
| Platform lock-in

| *Makefiles*
| `just`
| Fragile, implicit rules

| *Node.js*, *yarn*
| Bun
| Insecure by default; supply-chain risk
|===

The ban covers *toolchain declarations as well as source*, where that is
possible. A `mise.toml`, `.tool-versions` or container image that installs a
banned runtime is a violation, even if the repository tracks no source file
in that language (owner ruling 2026-11-26).

=== Exemptions

A banned language may appear only in the cases below. Each exemption covers
the minimum that its purpose needs, and nothing more.

. *Mending bad languages.* Work built to connect to, or reach into, a bad
  language so that it can be fixed. Examples: `proven`, `proven-servers`,
  `boj-server-cartridges`, `typesnake`.
. *Other people's code.* Forks and upstream projects, including
  MetaManifold-WebUI and MetaManifold data, and the forked lists in
  `stuff-of-awe`. Fix these upstream, not here.
. *Awesome lists.* A `stuff-of-awe` list about a language holds examples in
  that language. The list's own tooling follows this policy.
. *Handover archives.* Old V-lang or ReScript work in `developer-ecosystem`,
  kept only so others can take it on.
. *Special-purpose and verification languages.* ATS2, Verus, TLA+,
  miniKanren, ACL2 and similar, where the tool is the point, and the
  owner's own languages. The ATS2 entry is pending the matching change
  in the canonical standards text.
. *The PHP projects.* `php-aegis` and `sanctify-php` are the one standing
  exception. They are not converted.
. *Tiny oddities* such as TEA or REXX. Check each one is exceptional. They are
  not a route to keep other code.

Small add-ons are *not* exempt: Homebrew formulas, editor plugins and test
fixtures in a banned language. Each gets replaced or removed.

=== Mobile Development

No exceptions for Kotlin/Swift in our own code. Forks covered by
"Exemptions" keep their upstream mobile code. Use a Rust-first approach:

1. *Tauri 2.0+*: web UI (AffineScript) plus a Rust backend. MIT/Apache-2.0.
2. *Dioxus*: pure Rust native UI. MIT/Apache-2.0.

Both are FOSS with independent governance.

== Package Management Hierarchy

[cols="1,2"]
|===
| Priority | Tool

| *Primary*
| GNU Guix (`guix.scm` / `manifest.scm`)

| *Escape hatch*
| Sealed container (a `Containerfile` with real build steps)

| *JS deps*
| Bun (`package.json` + `bun.lock`)

Nix was retired estate-wide on 2026-06-01. It is not a fallback.

== Migration Priority

When encountering banned languages:

1. *Immediate*: Block new code and toolchain entries in banned languages.
2. *Short-term*: Strip banned runtimes from `mise.toml` and similar files.
   Move React to Vue. Convert small TypeScript and ReScript to AffineScript.
3. *Medium-term*: Port the large ReScript and TypeScript codebases to
   AffineScript, one repository at a time.
4. *Long-term*: Rewrite remaining Python, Ruby and Go in Rust or Julia.
   Move mobile code to Tauri or Dioxus.

== The Citadel of Code Creation

The *Citadel* is where RSR meets CCCP — the actual implementation pattern that embodies both.

=== What Makes It a "Citadel"?

* *Defensible Position* — Local dev environment can't be taken away by service outages
* *Self-Sufficient* — Guix + Podman + SaltRover = complete autonomy
* *Collective Defense* — Architecture makes mutual aid easier than isolation
* *Safe Haven* — Emotionally and technically safe to experiment

== Keepable Software

CCCP treats user ownership as an architectural property, not merely a licence statement.

Software should remain runnable, inspectable, forkable, exportable, and meaningfully ownable by the person who downloads it.

This does not require every project to reject the web, cloud services, sync, accounts, or hosted infrastructure. It requires that those service layers do not become the only place where the user's software, data, or work can exist.

CCCP therefore prefers projects that are web-first without being web-captive, local-first where practical, offline-capable where possible, and honest about remaining external dependencies.

Keepable Software is *one* of CCCP's aspirations, not the whole of it. It sits alongside the language policy, technical excellence, distributed state, formal verification, community, and offline-first autonomy described elsewhere in this manifesto — and it does not replace any of them. It is a better way of doing things rather than a new gate: part of the guarantee lives in the code (what runs locally, what is exportable, what is forkable), and part lives in the licence (what the user is legally free to keep, run, inspect, and fork). Good languages and sound engineering remain the foundation; keepability is one of the properties that foundation should produce.

In short:

[quote]
____
Download it. Keep it. Run it. Inspect it. Fork it.
Do not make the user's own work disappear behind someone else's switch.
____

Keepable Software is both an integral CCCP principle and a named thematic strand that adopter projects can reference. See <<_cccp_thematic_strands,CCCP Thematic Strands>> for the strand catalogue.

== CCCP Thematic Strands

CCCP principles may be expressed through named thematic strands: focused design commitments that projects can adopt, test, and refine.

Current strands include:

* link:docs/strands/keepable-software.adoc[Keepable Software] — web-first, not web-captive; downloadable, inspectable, forkable, exportable, and meaningfully runnable by the user.

== CCCP Certification

Projects can display CCCP certification when they:

1. Use only approved languages (see Language Policy)
2. Follow offline-first principles
3. Use FOSS tooling with independent governance
4. Implement reversibility patterns
5. Follow TPCF contribution model
